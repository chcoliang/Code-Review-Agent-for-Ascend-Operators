# A152 代码审查报告

## Bug 1: GetWorkspaceSize 与执行函数 API 版本不匹配

- **位置**: 第 39 行（声明）、第 136 行（调用）
- **类型**: API 版本不一致
- **严重程度**: 高
- **描述**: 第 39 行声明的是 `aclnnInnerScaledMaskedSoftmaxGetWorkspaceSize`（非 V2 版本），而第 43 行执行函数声明的是 `aclnnInnerScaledMaskedSoftmaxV2`（V2 版本）。GetWorkspaceSize 与实际执行函数版本不匹配，可能导致 workspace 大小计算与实际执行需求不一致，造成内存越界或计算错误。
- **触发条件**: 每次调用该算子时必然触发。如果非 V2 版本计算出的 workspaceSize 小于 V2 执行时实际需要的大小，将导致内存越界写入。
- **测试方案**: 
  1. 构造合法的 4D 输入 tensor（如 shape=[2,4,8,64]）调用完整流程，检查是否链接失败或运行时崩溃。
  2. 对比使用 V2 版 GetWorkspaceSize 返回的 workspaceSize 与当前非 V2 版返回值是否一致。

## Bug 2: 错误日志中 DIM_3 范围描述不准确

- **位置**: 第 106 行
- **类型**: 日志信息错误
- **严重程度**: 低
- **描述**: 错误信息固定写为 `"Expected x and mask dim4 in range of (0, 4096]."`，但当平台为 ASCEND910_95 时，实际限制为 8192。错误提示会误导用户。
- **触发条件**: 在 ASCEND910_95 平台上，传入 DIM_3 在 (4096, 8192] 范围内的 tensor 时触发错误提示，但提示信息不正确。
- **测试方案**: 在 ASCEND910_95 平台上传入 DIM_3=5000 的 tensor，验证不应报错；传入 DIM_3=9000 时验证错误信息是否准确反映 8192 的上限。
