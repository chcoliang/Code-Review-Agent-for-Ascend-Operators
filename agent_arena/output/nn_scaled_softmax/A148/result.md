# Code Review: aclnn_scaled_masked_softmax.cpp (A148)

## Bug 1: 错误日志中的维度限制值与实际逻辑不一致

- **位置**: 第 106 行
- **类型**: 逻辑错误 / 错误信息不一致
- **严重程度**: 中
- **描述**: 错误日志提示 `"Expected x and mask dim4 in range of (0, 4096]."`, 但实际代码中的限制值为 `D_LIMIT = 2048`（默认）或 `D_LIMIT_D = 8192`（910_95平台）。日志中硬编码的 4096 与任何一个实际限制值都不匹配，会误导用户排查问题。
- **触发条件**: 当 `x` 的第4维度超过 `dDimLimit`（2048 或 8192）时触发该错误日志，用户看到的提示信息与实际限制不符。
- **测试方案**: 在默认平台上传入 dim3=2049 的张量，观察错误信息是否提示 4096 上限（实际上限为 2048）；在 ASCEND910_95 平台传入 dim3=8193，错误信息仍提示 4096（实际上限为 8192）。

## Bug 2: x 与 y 的 shape 一致性未校验

- **位置**: 第 113-123 行 (`CheckParams` 函数)
- **类型**: 校验缺失
- **严重程度**: 中
- **描述**: `CheckParams` 中只校验了 x 与 mask 的 shape 关系，但未校验输出张量 y 的 shape 是否与 x 一致。如果 y 的 shape 与 x 不匹配，可能导致内存越界写入或结果错误。
- **触发条件**: 用户传入 shape 不匹配的 x 和 y 张量（例如 x=[2,4,8,64], y=[2,4,8,32]）。
- **测试方案**: 构造 x 和 y shape 不一致的用例，检查是否能正常报错或是否发生越界。

## Bug 3: namespace 内声明 extern 函数可能导致链接问题

- **位置**: 第 39-44 行
- **类型**: 设计缺陷
- **严重程度**: 低
- **描述**: `aclnnInnerScaledMaskedSoftmaxV2GetWorkspaceSize` 和 `aclnnInnerScaledMaskedSoftmaxV2` 在匿名 namespace 内部通过 `extern` 声明。匿名 namespace 具有内部链接属性，而 extern 要求外部链接，这在语义上存在矛盾。虽然大多数编译器对匿名 namespace 中的 extern 声明会按外部链接处理（因为它们引用的是已存在的外部符号），但这种写法不规范，可能在某些编译器或编译选项下导致链接失败。
- **触发条件**: 使用严格标准模式编译或特定编译器版本。
- **测试方案**: 使用 `-pedantic` 等严格编译选项编译，观察是否有警告或错误。

## Bug 4: fixedTriuMask 参数硬编码为 false 传递给内部函数

- **位置**: 第 136 行
- **类型**: 逻辑缺陷
- **严重程度**: 低
- **描述**: 当 `fixedTriuMask` 为 `false` 时（第132行检查通过），第136行将 `false` 硬编码传给内部函数，而非使用参数变量 `fixedTriuMask`。当前逻辑上等价（因为只有 false 能通过检查），但如果未来放开对 `fixedTriuMask=true` 的支持，开发者可能忘记修改此处硬编码，导致功能失效。
- **触发条件**: 未来代码修改放开 `fixedTriuMask=true` 的限制时，此处硬编码 false 会导致参数传递错误。
- **测试方案**: 注释掉第132-135行的检查后，传入 `fixedTriuMask=true`，验证内部函数是否收到正确的参数值。

## Bug 5: extern "C" 包裹了含 C++ 特性的匿名 namespace 代码

- **位置**: 第 26-27 行, 第 29-124 行, 第 146-147 行
- **类型**: 设计缺陷
- **严重程度**: 低
- **描述**: `extern "C"` 块从第27行开始，包含了匿名 namespace（第29行）中使用 `std::initializer_list`、`op::DataType` 等 C++ 特性的代码。`extern "C"` 的语义是使用 C 链接约定，虽然它不会改变内部代码的编译方式（C++ 编译器仍按 C++ 编译），但将纯 C++ 内部实现放在 `extern "C"` 块内是不规范的做法。正确做法是只将对外暴露的 C 接口函数放在 `extern "C"` 中。
- **触发条件**: 代码可正常编译运行，但违反最佳实践，可能在代码维护中引起混淆。
- **测试方案**: 代码审查，将匿名 namespace 移至 `extern "C"` 块外部，验证编译和功能不受影响。
