# Code Review: aclnn_scaled_masked_softmax.cpp (A139)

## Bug 1: DT_INT32 不应出现在 Softmax 支持的数据类型列表中

- **位置**: 第 35 行
- **类型**: 逻辑错误
- **严重程度**: 高
- **描述**: `SOFTMAX_X_DTYPE_SUPPORT_LIST` 中包含 `op::DataType::DT_INT32`。Softmax 是对浮点数进行指数运算和归一化的操作，对整数类型执行 Softmax 在数学上无意义，且可能导致精度丢失、溢出或未定义行为。
- **触发条件**: 用户传入 `DT_INT32` 类型的输入张量 `x`，校验通过后进入内部计算流程，产生错误结果或运行时异常。
- **测试方案**: 构造 `DT_INT32` 类型的 4D 输入张量，调用 `aclnnScaledMaskedSoftmaxGetWorkspaceSize`，验证是否返回错误码（预期应拒绝）；若未拒绝，执行算子验证输出正确性。

## Bug 2: 错误日志中 D_LIMIT 范围描述硬编码为 4096，与实际逻辑不一致

- **位置**: 第 106 行
- **类型**: 日志/提示信息错误
- **严重程度**: 中
- **描述**: 当平台为 `ASCEND910_95` 时，`dDimLimit` 被设置为 8192，但错误日志仍写死为 `"Expected x and mask dim4 in range of (0, 4096]."` 。当在 910_95 平台上 dim3 值在 (4096, 8192] 范围时不会触发此错误；但当 dim3 > 8192 时，打印的错误信息会误导用户认为上限是 4096。
- **触发条件**: 在 ASCEND910_95 平台上，传入 dim3 > 8192 的张量触发校验失败，日志显示的上限为 4096 而非 8192。
- **测试方案**: 在 ASCEND910_95 平台上传入 dim3=9000 的张量，检查返回的错误日志内容是否正确反映实际上限 8192。

## Bug 3: 输出张量 y 的 shape 未与输入 x 进行一致性校验

- **位置**: 第 113-123 行（`CheckParams` 函数）
- **类型**: 校验缺失
- **严重程度**: 中
- **描述**: `CheckParams` 中对 `y` 仅校验了维度数和数据类型，但未校验 `y` 的 shape 是否与 `x` 一致。Softmax 输出的 shape 应与输入完全相同，若 `y` 的 shape 与 `x` 不同，可能导致越界写入或结果截断。
- **触发条件**: 用户传入的输出张量 `y` shape 与 `x` 不一致（如某个维度更小），导致内部计算写越界。
- **测试方案**: 构造 x shape 为 [2,4,8,64]，y shape 为 [2,4,8,32] 的情况调用接口，验证是否正确报错。

## Bug 4: fixedTriuMask 参数在传递给内部函数时硬编码为 false

- **位置**: 第 136 行
- **类型**: 逻辑错误/功能限制未来兼容性
- **严重程度**: 低
- **描述**: 当 `fixedTriuMask` 为 `true` 时直接返回错误（第 132-135 行），但传给内部函数时硬编码为 `false` 而非使用参数 `fixedTriuMask`（此时必为 false）。当前逻辑等价正确，但如果未来移除前置检查而忘记修改此处，会导致参数丢失。这是一个维护性风险。
- **触发条件**: 未来代码修改移除第 132-135 行的前置检查后，`fixedTriuMask=true` 的语义丢失。
- **测试方案**: 代码审查确认；建议将第 136 行 `false` 替换为 `fixedTriuMask`。

## Bug 5: namespace 匿名空间内声明 extern 函数位于 `extern "C"` 块中

- **位置**: 第 25-27 行，第 29-124 行
- **类型**: 编译/链接错误风险
- **严重程度**: 中
- **描述**: `extern "C"` 块从第 26 行开始，匿名 namespace（第 29 行）位于其中。匿名 namespace 中的 `extern` 函数声明（第 39-44 行）具有内部链接，但 `extern` 要求外部链接，可能导致链接失败或未定义行为。此外，`extern "C"` 会影响匿名 namespace 内函数的 name mangling，逻辑上存在冲突。
- **触发条件**: 编译器对匿名 namespace 中 extern 声明的处理方式不同，某些编译器会报 warning 或 link error。
- **测试方案**: 在不同编译器（GCC/Clang）下编译验证是否有 warning 或链接错误。
