# Code Review: aclnn_scaled_masked_softmax.cpp (A145)

## Bug 1: mask 维度未校验为4维

- **位置**: 第66-71行 (`CheckTensorDim` 函数)
- **类型**: 输入校验缺失
- **严重程度**: 高
- **描述**: `CheckTensorDim` 函数对 `x` 和 `y` 做了4维校验，但未对 `mask` 做维度校验。后续 `CheckShape` 中直接使用 `mask->GetViewShape().GetDim(DIM_0)` 到 `DIM_3`，若 mask 不是4维张量，访问不存在的维度将导致未定义行为或崩溃。
- **触发条件**: 传入非4维的 mask 张量（例如2维或3维）。
- **测试方案**: 构造一个3维 mask（如 shape=[1,seq,seq]）与4维 x 一起调用，验证是否正确返回错误码而非崩溃。

## Bug 2: 错误日志中 D_LIMIT 值硬编码，与实际限制不一致

- **位置**: 第105行
- **类型**: 日志信息错误
- **严重程度**: 低
- **描述**: 错误日志写死 `"Expected x and mask dim4 in range of (0, 4096]."` ，但在 Ascend910_95 平台上实际限制为8192。用户在该平台上看到此报错信息会产生误导。
- **触发条件**: 在 ASCEND910_95 平台上，x 的第4维大小在 (4096, 8192] 范围内不会触发错误，但若超过8192则报错信息仍显示4096。
- **测试方案**: 在 ASCEND910_95 平台上传入 dim4=8193 的输入，检查报错信息是否正确反映8192的上限。

## Bug 3: x 和 y 的 shape 一致性未校验

- **位置**: 第112-121行 (`CheckParams` 函数)
- **类型**: 输入校验缺失
- **严重程度**: 高
- **描述**: `CheckShape` 只校验了 x 和 mask 的 shape 关系，但从未校验输出张量 y 的 shape 是否与 x 一致。若 y 的 shape 与 x 不匹配，算子执行时可能产生内存越界写入。
- **触发条件**: 传入 y 的 shape 与 x 不同（例如 x=[2,4,8,64]，y=[1,1,1,1]）。
- **测试方案**: 构造 x 为 [2,4,8,64]，y 为 [1,4,8,64]，调用接口验证是否返回参数错误。

## Bug 4: `extern "C"` 内部包含 namespace 和 C++ 特性

- **位置**: 第25-27行，第29-123行
- **类型**: 编码规范/潜在链接问题
- **严重程度**: 低
- **描述**: `extern "C"` 块内部定义了匿名 namespace，使用了 `std::initializer_list`、模板等 C++ 特性。虽然编译器通常能处理，但 `extern "C"` 的语义是使用 C 链接约定，将 C++ 代码放入其中不符合规范，且可能在部分编译器/链接器上引发名称修饰问题。实际上只有第125行和第139行的两个导出函数需要 C 链接。
- **触发条件**: 跨编译器或特殊链接场景下可能出现符号冲突。
- **测试方案**: 检查在不同编译器配置下是否能正常链接，或将匿名 namespace 移出 `extern "C"` 块。

## Bug 5: fixedTriuMask 参数强制传 false 给内部接口，忽略未来扩展

- **位置**: 第131-135行
- **类型**: 逻辑问题
- **严重程度**: 低
- **描述**: 当 `fixedTriuMask` 为 true 时直接报错返回，为 false 时也硬编码传 `false` 给内部接口。这本身不是 bug，但若未来需要支持 true 的场景，当前的硬编码方式需要修改。当前行为对用户而言，传入 true 只会得到一个拼写错误的日志（"suppport" 应为 "support"）。
- **触发条件**: 用户传入 fixedTriuMask=true。
- **测试方案**: 传入 fixedTriuMask=true，检查返回错误码是否正确，日志拼写是否影响问题定位。

## Bug 6: 错误日志拼写错误 "suppport"

- **位置**: 第132行
- **类型**: 拼写错误
- **严重程度**: 低
- **描述**: `"the param fixedTriuMask only suppport false."` 中 "suppport" 多了一个 'p'，应为 "support"。
- **触发条件**: 用户传入 fixedTriuMask=true 时触发该日志。
- **测试方案**: 代码静态检查即可发现。
