# Code Review: aclnn_scaled_masked_softmax.cpp (A145)

## Bug 列表

### Bug 1: 错误信息与实际限制不一致

- **位置**: 第 105 行
- **类型**: 逻辑错误 / 错误信息不准确
- **严重程度**: 中
- **描述**: 当平台为 `ASCEND910_95` 时，`dDimLimit` 被设为 8192（`D_LIMIT_D`），但错误日志硬编码为 `"Expected x and mask dim4 in range of (0, 4096]."`。在 910_95 平台上实际允许范围是 (0, 8192]，但报错提示仍然说 4096，会误导用户。
- **触发条件**: 在 ASCEND910_95 平台上，当 `x` 的第4维大于 8192 时触发该错误日志，用户看到的提示信息与实际限制不符。
- **测试方案**: 在 ASCEND910_95 平台上传入 dim3=8193 的 tensor，检查错误日志中是否正确显示 8192 而非 4096。

### Bug 2: 缺少 mask 张量的维度校验

- **位置**: 第 66-71 行 (`CheckTensorDim` 函数)
- **类型**: 输入校验缺失
- **严重程度**: 高
- **描述**: `CheckTensorDim` 仅检查了 `x` 和 `y` 的维度是否为 4，但没有检查 `mask` 的维度。后续 `CheckShape` 函数直接访问 `mask->GetViewShape().GetDim(DIM_0)` 到 `DIM_3`，如果 mask 维度不足 4（例如为 2D 或 3D），将导致越界访问或未定义行为。
- **触发条件**: 传入维度不为 4 的 mask 张量（如 shape 为 [seq_len, seq_len] 的 2D mask）。
- **测试方案**: 构造一个 2D 的 bool mask 张量传入，验证是否在 `CheckTensorDim` 阶段即返回错误，而非在 `CheckShape` 中产生崩溃。

### Bug 3: 缺少输出张量 y 与输入张量 x 的 shape 一致性校验

- **位置**: 第 112-121 行 (`CheckParams` 函数)
- **类型**: 输入校验缺失
- **严重程度**: 中
- **描述**: 代码检查了 x 与 mask 的 shape 广播关系，但从未验证输出张量 `y` 的 shape 是否与 `x` 一致。Scaled Masked Softmax 的输出 shape 应与输入 x 相同，若 y 的 shape 不匹配，会导致计算结果写入错误的内存区域或数据截断。
- **触发条件**: 传入与 x shape 不一致的 y 张量（如 x 为 [2,8,512,64] 但 y 为 [2,8,512,128]）。
- **测试方案**: 构造 x=[2,8,512,64]、y=[2,8,512,128] 的张量对，调用该接口验证是否报错。

### Bug 4: extern "C" 包裹了含 C++ 特性的匿名命名空间

- **位置**: 第 25-27 行和第 145-147 行
- **类型**: 编码规范 / 潜在兼容性问题
- **严重程度**: 低
- **描述**: `extern "C"` 块内包含了匿名 namespace、`std::initializer_list`、模板等 C++ 特性。虽然大多数编译器对此容忍（仅对导出函数应用 C 链接），但这不符合 `extern "C"` 的语义，且在某些严格编译器配置下可能产生警告或错误。正确做法是仅将需要 C 链接的两个导出函数放在 `extern "C"` 块内，将匿名 namespace 移到块外。
- **触发条件**: 使用严格 C++ 标准模式编译或切换编译器版本时可能触发警告。
- **测试方案**: 使用 `-pedantic` 编译选项检查是否产生诊断信息。
