# Code Review: aclnn_scaled_masked_softmax.cpp (A144)

## Bug 1: 错误日志中 D_LIMIT 硬编码与实际逻辑不一致

- **位置**: 第 106 行
- **类型**: 逻辑错误 / 错误信息不准确
- **严重程度**: 中
- **描述**: 当 SoC 为 ASCEND910_95 时，`dDimLimit` 被设为 8192，但错误日志仍固定输出 `"Expected x and mask dim4 in range of (0, 4096]."` ，对用户产生误导。应根据实际 `dDimLimit` 值动态输出正确范围。
- **触发条件**: 在 ASCEND910_95 平台上，当 `DIM_3` 在 (4096, 8192] 范围内时不会触发错误（正确行为），但当 `DIM_3 > 8192` 时会触发错误，打印的错误信息中范围仍然写 4096，与实际限制 8192 不符。
- **测试方案**: 在 ASCEND910_95 平台构造 `DIM_3 = 8193` 的 tensor，触发该分支，验证错误日志输出内容是否正确显示 8192。

## Bug 2: 未校验 x 与 y 的 shape 一致性

- **位置**: 第 113-123 行 (`CheckParams` 函数)
- **类型**: 校验缺失
- **严重程度**: 高
- **描述**: `CheckParams` 中仅校验了 x 与 mask 的 shape 关系，未校验输出 tensor `y` 的 shape 是否与输入 `x` 一致。Softmax 算子的输出 shape 应与输入完全相同，缺少此校验可能导致写越界或计算结果错误。
- **触发条件**: 传入的 `y` tensor shape 与 `x` 不同（例如维度更小），导致内核写入越界或结果异常。
- **测试方案**: 构造 x shape 为 [2,4,8,64]，y shape 为 [1,1,1,1]，调用接口观察是否能正确报错或是否产生内存越界。

## Bug 3: namespace 匿名空间内声明 extern 函数位于 extern "C" 块中

- **位置**: 第 25-27 行, 第 29-124 行
- **类型**: 链接/编译问题
- **严重程度**: 中
- **描述**: `extern "C"` 块在第 26 行开启，而匿名 namespace 在第 29 行开始，其中第 39-44 行使用 `extern` 声明了两个函数 (`aclnnInnerScaledMaskedSoftmaxV2GetWorkspaceSize` 和 `aclnnInnerScaledMaskedSoftmaxV2`)。匿名 namespace 赋予内部链接属性，与 `extern` 声明的外部链接属性冲突。在 `extern "C"` 内部的匿名 namespace 中 extern 声明外部 C 函数，行为依赖编译器实现，可能导致链接失败。
- **触发条件**: 在某些编译器或编译选项下，匿名 namespace 内的 extern 声明无法正确链接到外部符号。
- **测试方案**: 使用不同编译器版本（GCC/Clang）编译该文件，检查是否产生链接错误或警告。

## Bug 4: fixedTriuMask 参数被忽略但接口仍暴露

- **位置**: 第 132-135 行
- **类型**: 设计缺陷 / 接口一致性
- **严重程度**: 低
- **描述**: `fixedTriuMask` 参数为 `true` 时直接返回错误，且在调用内部函数时硬编码传 `false`（第 136 行）。这意味着该参数在当前实现中完全无效，但接口签名仍保留该参数，可能误导用户认为支持 `fixedTriuMask = true` 的功能。
- **触发条件**: 用户传入 `fixedTriuMask = true`。
- **测试方案**: 传入 `fixedTriuMask = true`，验证是否返回明确错误码和合理错误信息。

## Bug 5: DIM_3 边界检查不包含 0 值校验

- **位置**: 第 105 行
- **类型**: 边界校验不完整
- **严重程度**: 中
- **描述**: 检查条件为 `x->GetViewShape().GetDim(DIM_3) > dDimLimit`，仅判断上限，未检查 `DIM_3 <= 0` 的情况。错误日志提示范围为 `(0, 4096]`，暗示 0 值非法，但代码未对此做检查。若 DIM_3 为 0，可能导致内核计算异常（如除零、空 buffer 等）。
- **触发条件**: 传入 DIM_3 = 0 的 tensor。
- **测试方案**: 构造 DIM_3 = 0 的 x tensor，调用接口验证是否产生正确报错或导致崩溃。
