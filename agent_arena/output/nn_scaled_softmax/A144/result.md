# Code Review: aclnn_scaled_masked_softmax.cpp (A144)

## Bug 列表

### Bug 1: 错误日志信息与实际限制不一致

- **位置**: 第106行
- **类型**: 逻辑错误 / 日志信息错误
- **严重程度**: 中
- **描述**: 当平台为 ASCEND910_95 时，`dDimLimit` 被设为 8192，但错误日志硬编码为 `"Expected x and mask dim4 in range of (0, 4096]."`。这会在 910_95 平台上误导用户，实际限制是 8192 而非 4096。
- **触发条件**: 在 ASCEND910_95 平台上，当 `x` 的第4维大于 4096 但小于等于 8192 时不会报错（正确行为），但当大于 8192 时报错信息仍显示上限为 4096。
- **测试方案**: 在 ASCEND910_95 平台上构造 dim3 = 9000 的输入张量，验证报错信息应显示 8192 而非 4096。

---

### Bug 2: fixedTriuMask 参数被强制忽略，传入 false 给内部函数

- **位置**: 第136行
- **类型**: 功能限制 / 潜在逻辑错误
- **严重程度**: 低
- **描述**: 当 `fixedTriuMask` 为 `true` 时直接返回错误（第132-135行），当为 `false` 时调用内部函数也硬编码传入 `false`（第136行）。虽然当前只支持 `false`，但硬编码 `false` 而非直接传入参数 `fixedTriuMask` 是冗余且不利于未来扩展的。如果未来移除前面的检查但忘记修改此处，将导致功能永远无法启用。
- **触发条件**: 未来扩展支持 `fixedTriuMask=true` 时若只移除检查而未修改第136行。
- **测试方案**: 代码审查确认，确保参数传递一致性。

---

### Bug 3: CheckShape 未校验 x 与 y 的 shape 一致性

- **位置**: 第75-111行 及第113-123行 `CheckParams` 函数
- **类型**: 校验缺失
- **严重程度**: 高
- **描述**: `CheckParams` 只校验了 x 与 mask 的 shape 关系，但从未校验输出张量 `y` 的 shape 是否与 `x` 一致。如果用户传入 shape 不匹配的 `y`，将导致内存越界写入或计算结果错误。
- **触发条件**: 用户传入 `y` 的 shape 与 `x` 不同（如维度大小不一致），函数不会报错，直接传入内层函数执行，可能导致内存越界。
- **测试方案**: 构造 x.shape=[2,4,8,16] 但 y.shape=[2,4,8,32] 的输入，验证是否能正确拦截并返回错误。

---

### Bug 4: namespace 内声明 extern 函数放在 extern "C" 块内

- **位置**: 第25-27行 (`extern "C"`) 与第29行 (匿名 namespace)
- **类型**: 编译/链接错误风险
- **严重程度**: 中
- **描述**: `extern "C"` 块包裹了整个匿名 namespace 及其中的 `extern` 函数声明（第39-44行）。匿名 namespace 中的 extern 函数声明在 `extern "C"` 语义下可能导致链接问题——匿名 namespace 赋予内部链接，而 `extern "C"` 期望外部链接，两者语义冲突。此外，匿名 namespace 中声明外部函数本身就是不规范的做法。
- **触发条件**: 不同编译器对此处理不同，可能在某些编译器版本下出现链接失败或符号找不到的问题。
- **测试方案**: 使用不同版本编译器（GCC/Clang）编译此文件，检查是否有链接警告或错误。

---

### Bug 5: DIM_3 限制检查缺少下界校验

- **位置**: 第105-108行
- **类型**: 校验缺失
- **严重程度**: 中
- **描述**: 错误日志提示范围为 `(0, 4096]`，暗示 dim3 必须大于 0，但代码只检查了 `> dDimLimit` 的上界，未检查 `<= 0` 的下界。如果 dim3 为 0 或负值，将跳过此检查，可能在后续计算中导致除零或非法内存访问。
- **触发条件**: 传入 x 的第4维为 0（空张量情况）。
- **测试方案**: 构造 x.shape=[2,4,8,0] 的输入，验证是否正确拦截。
