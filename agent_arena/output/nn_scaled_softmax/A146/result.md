# Code Review: aclnn_scaled_masked_softmax.cpp (A146)

## Bug List

### Bug 1: 缺少对输入张量 x 的维度校验

- **位置**: 第 66-71 行, `CheckTensorDim` 函数
- **类型**: 逻辑缺陷 / 输入校验遗漏
- **严重程度**: 高
- **描述**: `CheckTensorDim` 函数只校验了 `mask` 和 `y` 是否为 4 维张量，但遗漏了对 `x` 的维度校验。`x` 同样要求是 4 维张量（后续 `CheckShape` 中直接通过 `DIM_0` ~ `DIM_3` 访问 `x` 的各维度），若 `x` 维度不足 4，将导致越界访问或未定义行为。
- **触发条件**: 传入维度不为 4 的张量 `x`（例如 3 维或 5 维张量），跳过维度校验后进入 `CheckShape`，访问不存在的维度索引。
- **测试方案**: 构造一个 3 维张量作为 `x` 输入（如 shape=[2,3,4]），`mask` 和 `y` 为合法 4 维张量，调用 `aclnnScaledMaskedSoftmaxGetWorkspaceSize`，预期应返回 `ACLNN_ERR_PARAM_INVALID`，实际可能崩溃或返回错误结果。

---

### Bug 2: 错误信息与实际限制不一致（硬编码错误提示）

- **位置**: 第 105 行, `CheckShape` 函数
- **类型**: 错误信息误导
- **严重程度**: 中
- **描述**: 错误日志硬编码为 `"Expected x and mask dim4 in range of (0, 4096]."`，但当运行在 Ascend910_95 平台时，实际限制为 8192（`D_LIMIT_D`）。错误提示未反映真实的动态限制值，会误导用户排查问题。
- **触发条件**: 在 Ascend910_95 平台上，传入 `DIM_3` 大小为 5000 的张量（合法范围内应通过），如果传入大小为 9000 的张量（超出 8192 限制），报错信息错误地提示上限为 4096。
- **测试方案**: 在 Ascend910_95 环境下，传入 `x` 的 `DIM_3=8000`，应合法通过；传入 `DIM_3=9000`，应报错且错误信息应显示正确上限 8192 而非 4096。

---

### Bug 3: CheckShape 中对 x 的维度越界访问风险

- **位置**: 第 76、84、93、94、104 行, `CheckShape` 函数
- **类型**: 潜在越界访问 / 未定义行为
- **严重程度**: 高
- **描述**: `CheckShape` 直接使用 `x->GetViewShape().GetDim(DIM_0)` 至 `GetDim(DIM_3)` 访问张量维度，但由于 Bug 1 的存在，`x` 的维度未经校验。如果 `x` 维度数小于 4，`GetDim(DIM_3)` 等调用可能越界，导致段错误或返回垃圾值。此 bug 是 Bug 1 的直接后果。
- **触发条件**: 与 Bug 1 相同 —— 传入维度小于 4 的 `x` 张量。
- **测试方案**: 同 Bug 1，使用低维张量作为 `x` 输入，观察是否触发 crash 或异常行为。

---

### Bug 4: fixedTriuMask 参数被硬编码忽略传递

- **位置**: 第 135 行
- **类型**: 逻辑缺陷 / 参数传递错误
- **严重程度**: 低
- **描述**: 调用 `aclnnInnerScaledMaskedSoftmaxV2GetWorkspaceSize` 时，`fixedTriuMask` 参数被硬编码为 `false`，而非传递用户输入值。虽然当前第 131-134 行限制了 `fixedTriuMask` 只能为 `false`，但这种硬编码方式不利于后续扩展。若未来移除该限制但忘记修改第 135 行，将导致用户传入 `true` 时功能失效且无任何报错。
- **触发条件**: 当前不会触发（因为有前置校验）。未来移除 `fixedTriuMask` 为 true 的限制后，传入 `fixedTriuMask=true` 时，实际底层仍以 `false` 执行。
- **测试方案**: 移除第 131-134 行的限制后，传入 `fixedTriuMask=true`，验证底层算子是否真正以上三角 mask 模式执行。
