# Code Review Report: aclnn_scaled_masked_softmax.cpp

## Bug List

### Bug 1: 错误信息与实际限制不一致

- **位置**: 第 101 行
- **类型**: 逻辑错误 / 错误信息不准确
- **严重程度**: 中
- **描述**: 错误信息硬编码为 `"Expected x and mask dim4 in range of (0, 4096]."`, 但当 SoC 版本为 `ASCEND910_95` 时, 实际限制 `dDimLimit` 为 8192 (`D_LIMIT_D`)。用户在该平台上传入大小为 5000 的合法 DIM_3 时不会被拒绝, 但如果被拒绝, 错误提示会误导用户。更严重的是, 当 DIM_3=5000 在 ASCEND910_95 上实际合法时, 错误消息暗示上限为 4096, 导致调试困难。
- **触发条件**: 在 ASCEND910_95 平台上, 当 `x` 的 DIM_3 > 8192 时触发该错误日志, 打印的上限 4096 与实际 8192 不符。
- **测试方案**: 在 ASCEND910_95 平台上构造 DIM_3=9000 的 tensor, 验证错误日志应提示上限为 8192 而非 4096。

---

### Bug 2: 缺少 mask 与 x 在 DIM_2 和 DIM_3 上的广播兼容性校验

- **位置**: 第 75-106 行 (`CheckShape` 函数)
- **类型**: 校验缺失
- **严重程度**: 高
- **描述**: `CheckShape` 函数仅校验了 `x` 与 `mask` 在 DIM_0 和 DIM_1 上的广播兼容性, 但完全没有校验 DIM_2 和 DIM_3。如果 mask 在这两个维度上与 x 既不相同也不为 1, 将导致后续内核计算时出现越界访问或计算结果错误。
- **触发条件**: 传入 `x` shape 为 `[B, H, S, D]`, `mask` shape 为 `[B, H, S', D']` 其中 `S' != S && S' != 1` 或 `D' != D && D' != 1`。
- **测试方案**: 构造 `x` shape `[2, 4, 8, 16]`, `mask` shape `[2, 4, 5, 16]`, 调用 API 应返回 `ACLNN_ERR_PARAM_INVALID` 但当前会通过校验进入内核导致未定义行为。

---

### Bug 3: 缺少输出张量 y 与输入张量 x 的 shape 一致性校验

- **位置**: 第 108-118 行 (`CheckParams` 函数)
- **类型**: 校验缺失
- **严重程度**: 高
- **描述**: `CheckParams` 校验了 x 与 y 的 dtype 一致性和维度数, 但未校验 y 的 shape 是否与 x 完全相同。Softmax 是逐元素操作, 输出 shape 必须与输入 shape 一致。如果 y 的 shape 与 x 不同, 内核可能写越界或产生错误结果。
- **触发条件**: 传入 `x` shape `[2, 4, 8, 16]`, `y` shape `[2, 4, 8, 32]`(dtype 和维度数都匹配), 校验通过但实际计算错误。
- **测试方案**: 构造 x 和 y 具有相同 dtype、相同维度数但不同 shape, 验证应在校验阶段被拒绝。

---

### Bug 4: `fixedTriuMask` 参数校验位置不当导致空指针风险已规避但语义冗余

- **位置**: 第 127-131 行
- **类型**: 设计缺陷
- **严重程度**: 低
- **描述**: 当 `fixedTriuMask=true` 时, 函数返回错误, 当 `fixedTriuMask=false` 时, 在第 131 行又硬编码传入 `false`。参数 `fixedTriuMask` 对调用者无意义 — 传 `true` 报错, 传 `false` 等同于不存在。虽然不会导致运行时错误, 但属于接口设计问题, 可能表明后续应支持 `true` 的情况但实现未完成。
- **触发条件**: 用户传入 `fixedTriuMask=true`。
- **测试方案**: 验证 `fixedTriuMask=true` 时返回 `ACLNN_ERR_PARAM_INVALID`; 确认文档是否标注该参数当前不支持。
