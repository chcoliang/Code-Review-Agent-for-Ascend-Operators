# A234 - test_scaled_softmax_pipeline.cpp 代码审查报告

## Bug 1: 缺少流同步导致 memcpy 读取未计算完成的数据

- **位置**: 第 12-13 行
- **类型**: 同步缺陷
- **严重程度**: 高
- **描述**: 代码在第 8-10 行分配了 x、mask、y 设备内存，但在第 13 行直接用 `aclrtMemcpy` 从 y 拷贝数据到 host。中间没有任何算子下发到 stream，也没有调用 `aclrtSynchronizeStream(stream)` 进行流同步。如果实际使用场景中有异步算子在 stream 上操作 y，则 memcpy 会读取到未完成计算的脏数据。即使当前代码没有算子下发，缺少同步也是流水线编程模式的严重缺陷。
- **触发条件**: 当 stream 上有异步算子操作 y 时，memcpy 读取到的数据不确定。
- **测试方案**:
  1. 在 memcpy 前插入 `aclrtSynchronizeStream(stream)` 后对比结果一致性。
  2. 添加异步算子后验证不加同步时数据是否正确。

## Bug 2: 读取未初始化的设备内存

- **位置**: 第 13 行
- **类型**: 未初始化数据使用
- **严重程度**: 中
- **描述**: `aclrtMalloc` 分配的设备内存 y 未经任何初始化或算子写入，直接通过 `aclrtMemcpy` 拷贝到 host 缓冲区 h。读取到的是未定义的随机数据，在 pipeline 测试中无法验证正确性。
- **触发条件**: 程序执行即触发，y 中内容不确定。
- **测试方案**: 在分配后用 `aclrtMemset` 初始化 y 或下发算子写入 y，再 memcpy 验证数据正确性。

## Bug 3: host 缓冲区 h 仅 4KB 但 y 为 16MB，pipeline 测试覆盖不足

- **位置**: 第 12-13 行
- **类型**: 逻辑缺陷
- **严重程度**: 低
- **描述**: host 端 `float h[1024]` 大小为 4096 字节，而 y 的设备内存为 `4*8*512*512*2 = 16MB`。memcpy 只拷贝了 4KB，作为 pipeline 正确性验证覆盖率极低。
- **触发条件**: 当 pipeline 输出后半段有错误时，该测试无法发现。
- **测试方案**: 扩大 h 缓冲区或分段拷贝全部数据进行校验。

## Bug 4: 缺少 API 返回值检查

- **位置**: 第 3、4、6、8、9、10、13 行
- **类型**: 错误处理缺失
- **严重程度**: 低
- **描述**: 所有 ACL API 调用均未检查返回值。若任何一步失败（如内存分配失败），后续操作将使用无效指针。
- **触发条件**: 设备内存不足或设备异常时。
- **测试方案**: 注入故障（如限制可用内存），验证程序是否正确处理错误。
