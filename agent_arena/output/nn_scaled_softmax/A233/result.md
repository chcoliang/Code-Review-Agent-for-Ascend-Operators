# A233 - test_scaled_softmax_stress.cpp 代码审查报告

## Bug 1: 循环内设备内存泄漏

- **位置**: 第 9 行（循环体内 `aclrtMalloc`）
- **类型**: 资源泄漏（内存泄漏）
- **严重程度**: 高
- **描述**: 在 `for` 循环中（1000次迭代），每次迭代调用 `aclrtMalloc` 分配 16MB 设备内存，但循环体内没有调用 `aclrtFree(ws)` 释放内存。每次循环重新声明 `ws` 指针，前一次分配的地址丢失，导致累计泄漏 1000 * 16MB = 16GB 设备内存。
- **触发条件**: 程序执行即触发。循环运行数次后设备内存耗尽，后续 `aclrtMalloc` 将返回错误码。
- **测试方案**:
  1. 在循环前后通过 `aclrtGetMemInfo` 查询设备可用内存，对比差值应接近 0（修复后）或约 16GB（修复前）。
  2. 运行程序并检查 `aclrtMalloc` 返回值，验证是否因 OOM 返回失败。
  3. 使用 NPU 内存分析工具（如 msprof）检测泄漏。

## Bug 2: 缺少 aclrtMalloc 返回值检查

- **位置**: 第 9 行
- **类型**: 错误处理缺失
- **严重程度**: 中
- **描述**: `aclrtMalloc` 的返回值未检查。当设备内存不足时，分配失败但程序继续执行，可能导致后续使用空指针访问设备内存。
- **触发条件**: 设备可用内存不足时分配失败。
- **测试方案**: 在内存紧张条件下运行，检查返回值是否为 `ACL_SUCCESS`。

## Bug 3: aclInit/aclrtSetDevice/aclrtCreateStream 返回值未检查

- **位置**: 第 3、4、6 行
- **类型**: 错误处理缺失
- **严重程度**: 低
- **描述**: 初始化阶段的 ACL API 调用均未做返回值检查，若设备不可用或初始化失败，程序将在未定义状态下继续执行。
- **触发条件**: 设备离线或驱动异常时。
- **测试方案**: 在无 NPU 设备环境下运行，验证是否优雅退出。
