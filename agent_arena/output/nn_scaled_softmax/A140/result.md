# Code Review: aclnn_scaled_masked_softmax.cpp

## Bug 列表

### Bug 1: 空指针检查失败时返回成功状态码

- **位置**: 第 115 行
- **类型**: 逻辑错误
- **严重程度**: 严重 (Critical)
- **描述**: `CHECK_RET(CheckNotNull(x, mask, y), ACLNN_SUCCESS);` 当 `CheckNotNull` 返回 `false`（即检测到空指针）时，`CHECK_RET` 宏会返回第二个参数 `ACLNN_SUCCESS`。这意味着即使输入为空指针，函数仍然返回成功，后续代码将对空指针解引用导致崩溃。应改为 `ACLNN_ERR_PARAM_INVALID`。
- **触发条件**: 传入 `x`、`mask` 或 `y` 为 `nullptr` 时触发。
- **测试方案**: 调用 `aclnnScaledMaskedSoftmaxGetWorkspaceSize` 并将任一 tensor 参数设为 `nullptr`，验证返回值应为错误码而非 `ACLNN_SUCCESS`。

### Bug 2: 错误信息与实际限制不一致

- **位置**: 第 106 行
- **类型**: 错误信息不准确
- **严重程度**: 中等 (Medium)
- **描述**: 错误日志硬编码为 `"Expected x and mask dim4 in range of (0, 4096]."`, 但当平台为 `ASCEND910_95` 时，实际限制是 `D_LIMIT_D = 8192`。用户在该平台上收到误导性的错误信息，影响问题定位。
- **触发条件**: 在 Ascend910_95 平台上，输入 tensor 第4维大于 8192 时触发，用户看到的错误提示上限为 4096，与实际不符。
- **测试方案**: 在 Ascend910_95 平台上，传入第4维为 5000 的 tensor（合法值），确认不报错；传入 9000 时确认报错信息包含正确上限 8192。

### Bug 3: 缺少输出 tensor y 与输入 tensor x 的 shape 一致性校验

- **位置**: 第 75-111 行 (`CheckShape` 函数)
- **类型**: 校验遗漏
- **严重程度**: 中等 (Medium)
- **描述**: `CheckShape` 函数只校验了 `x` 和 `mask` 之间的 shape 关系，但未校验输出 tensor `y` 的 shape 是否与 `x` 一致。若 `y` 的 shape 与 `x` 不匹配，可能导致内存越界写入或计算结果错误。
- **触发条件**: 传入的 `y` tensor shape 与 `x` 不一致（例如 `x` 为 `[2,4,8,16]`，`y` 为 `[1,1,1,1]`）。
- **测试方案**: 构造 `x` shape 为 `[2,4,8,64]`，`y` shape 为 `[1,1,1,1]`，调用接口验证是否正确报错拒绝。

### Bug 4: extern "C" 包含 C++ 结构和匿名命名空间

- **位置**: 第 26-27 行开始，第 146-147 行结束
- **类型**: 语言规范违规
- **严重程度**: 低 (Low)
- **描述**: `extern "C"` 块内包含了匿名 `namespace`、`std::initializer_list`、以及在匿名命名空间内声明的 `extern` 函数。`extern "C"` 的语义是使用 C 链接，但内部使用了纯 C++ 特性。虽然大多数编译器能容忍，但在匿名命名空间中声明 `extern` 函数（第 39-44 行）具有内部链接，与 `extern` 声明矛盾，可能导致链接失败。
- **触发条件**: 使用严格模式编译或不同编译器版本时可能产生编译警告或链接错误。
- **测试方案**: 使用 `-pedantic` 编译选项编译，检查是否有警告或错误。

### Bug 5: fixedTriuMask 参数被忽略，硬编码传 false

- **位置**: 第 136 行
- **类型**: 功能限制/接口设计缺陷
- **严重程度**: 低 (Low)
- **描述**: 第 132-134 行已检查 `fixedTriuMask` 若为 `true` 则报错返回，第 136 行传给内部函数时硬编码为 `false` 而非传递参数值。虽然当前逻辑上不会出错（true 已被拦截），但这种写法意味着未来若放开 `true` 支持时容易遗忘修改此处，属于代码可维护性问题。
- **触发条件**: 未来代码演进删除第 132-134 行的限制后，`fixedTriuMask=true` 将永远无法生效。
- **测试方案**: 代码审查确认；若未来移除限制，需同步修改第 136 行为传递原始参数。
