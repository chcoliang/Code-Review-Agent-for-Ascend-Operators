# A221 - test_swish_lifecycle.cpp 代码审查报告

## Bug 1: 循环内 TensorDesc 资源泄漏

- **位置**: 第 7 行（`aclCreateTensorDesc`）
- **类型**: 资源泄漏
- **严重程度**: 高
- **描述**: 在循环内通过 `aclCreateTensorDesc` 创建张量描述符，但循环体内没有调用 `aclDestroyTensorDesc(d)` 释放。循环 100 次后累计泄漏 100 个 TensorDesc 对象。
- **触发条件**: 程序正常执行即触发，循环迭代次数 > 0 时必现。
- **修复建议**: 在循环体末尾添加 `aclDestroyTensorDesc(d);`。
- **测试方案**: 增大循环次数（如 100000），监控进程内存增长；或使用内存分析工具（如 valgrind）检测泄漏。

## Bug 2: 循环内 DataBuffer 资源泄漏

- **位置**: 第 8 行（`aclCreateDataBuffer`）
- **类型**: 资源泄漏
- **严重程度**: 高
- **描述**: 在循环内通过 `aclCreateDataBuffer` 创建数据缓冲区描述符，但循环体内没有调用 `aclDestroyDataBuffer(b)` 释放。循环 100 次后累计泄漏 100 个 DataBuffer 对象。
- **触发条件**: 程序正常执行即触发。
- **修复建议**: 在循环体末尾添加 `aclDestroyDataBuffer(b);`。
- **测试方案**: 同 Bug 1，使用内存分析工具检测。

## Bug 3: aclCreateDataBuffer 传入 nullptr 指针

- **位置**: 第 8 行
- **类型**: 逻辑错误
- **严重程度**: 中
- **描述**: `aclCreateDataBuffer(nullptr, 16*4096*2)` 传入的数据指针为 `nullptr`，创建了一个没有实际设备内存支撑的 DataBuffer。若后续将此 buffer 用于算子执行，将导致访问空指针或非法内存访问。
- **触发条件**: 将该 DataBuffer 作为算子输入/输出使用时触发。
- **修复建议**: 先通过 `aclrtMalloc` 分配设备内存，再传入有效指针。
- **测试方案**: 将该 DataBuffer 作为 swish 算子输入执行，验证是否触发设备侧内存访问错误。

## Bug 4: 缺少 Stream 创建与销毁

- **位置**: 全文
- **类型**: 资源管理不完整
- **严重程度**: 低
- **描述**: 作为生命周期测试，缺少 stream 的创建和销毁，如果后续需要在 stream 上执行算子，将缺少必要资源。
- **触发条件**: 需要执行异步算子操作时。
- **测试方案**: 补充算子执行逻辑，验证缺少 stream 时的行为。

## Bug 5: 缺少 API 返回值检查

- **位置**: 第 3、4、7、8 行
- **类型**: 错误处理缺失
- **严重程度**: 低
- **描述**: 所有 ACL API 调用均未检查返回值，若创建失败则返回的指针为 nullptr，后续使用将导致问题。
- **触发条件**: 资源耗尽或参数非法时。
- **测试方案**: 传入非法参数验证失败处理。
