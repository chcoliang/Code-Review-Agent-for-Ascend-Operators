# A220 - test_swish_pipeline.cpp 代码审查报告

## Bug 1: 缺少流同步导致读取未完成的异步结果

- **位置**: 第 13 行（`aclrtMemcpy` 调用之前）
- **类型**: 同步缺失
- **严重程度**: 高
- **描述**: 第 10 行注释表明在 stream 上启动了 swish 算子（异步执行），但在第 13 行使用 `aclrtMemcpy`（同步拷贝）读取输出前，没有调用 `aclrtSynchronizeStream(stream)` 等待算子执行完成。这导致拷贝回主机的数据可能是未计算完成的脏数据或全零数据。
- **触发条件**: 算子实际被提交到 stream 异步执行时必现；在算子执行耗时较长时更明显。
- **修复建议**: 在 `aclrtMemcpy` 之前添加 `aclrtSynchronizeStream(stream);`。
- **测试方案**: 提交一个耗时较长的 swish 算子，比较有无同步时拷贝回的数据是否一致，验证无同步时数据错误。

## Bug 2: aclrtMemcpy 使用同步拷贝但未验证数据正确性

- **位置**: 第 13 行
- **类型**: 逻辑错误
- **严重程度**: 中
- **描述**: `aclrtMemcpy` 使用 `ACL_MEMCPY_DEVICE_TO_HOST` 是同步操作（相对于 host），但它不会等待 stream 上的算子完成。即使 memcpy 本身完成了，拷贝的数据源（`out` 缓冲区）内容可能尚未被算子写入。这与 Bug 1 本质相同但从不同角度描述：用户可能误以为同步 memcpy 会隐式等待 stream。
- **触发条件**: 同 Bug 1。
- **测试方案**: 同 Bug 1。

## Bug 3: 缺少 API 返回值检查

- **位置**: 第 3、4、6、8、9、13、14 行
- **类型**: 错误处理缺失
- **严重程度**: 低
- **描述**: 所有 ACL API 调用均未检查返回值。若任一步骤失败（如内存分配失败），后续操作将使用无效指针。
- **触发条件**: 设备资源不足或环境异常时。
- **测试方案**: 在资源受限环境中运行，验证是否有合理错误处理。
