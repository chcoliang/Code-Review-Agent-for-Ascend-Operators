# A219 - test_swish_stress.cpp 代码审查报告

## Bug 1: 循环内设备内存泄漏

- **位置**: 第 9 行（循环体内 `aclrtMalloc`）
- **类型**: 资源泄漏（内存泄漏）
- **严重程度**: 高
- **描述**: 在 `for` 循环中每次迭代分配 16MB 设备内存（`aclrtMalloc`），但循环体内没有对应的 `aclrtFree(ws)` 释放。循环执行 1000 次，累计泄漏 16GB 设备内存。
- **触发条件**: 程序正常执行即触发，循环迭代次数 > 0 时必现。
- **修复建议**: 在循环体末尾添加 `aclrtFree(ws);`。
- **测试方案**: 运行程序并监控 NPU 设备内存使用（如 `npu-smi info`），观察内存是否持续增长；或在循环后检查 `aclrtGetMemInfo` 确认可用内存未减少。

## Bug 2: 缺少 aclrtMalloc 返回值检查

- **位置**: 第 9 行
- **类型**: 错误处理缺失
- **严重程度**: 中
- **描述**: `aclrtMalloc` 可能因设备内存耗尽而失败（尤其在累计泄漏场景下），但未检查返回值。失败后 `ws` 仍为 `nullptr`，若后续有操作该指针的逻辑将导致未定义行为。
- **触发条件**: 设备内存不足时（由于 Bug 1 的泄漏，大约迭代数百次后即会触发）。
- **测试方案**: 在内存受限环境中运行，或将分配大小设置为超大值，验证程序是否能正确处理分配失败。

## Bug 3: 缺少 aclInit/aclrtSetDevice/aclrtCreateStream 返回值检查

- **位置**: 第 3、4、6 行
- **类型**: 错误处理缺失
- **严重程度**: 低
- **描述**: 初始化相关 API 调用均未检查返回值，若初始化失败，后续所有操作行为未定义。
- **触发条件**: 设备不可用或驱动异常时。
- **测试方案**: 在无 NPU 设备的环境中运行，验证是否有合理错误退出。
