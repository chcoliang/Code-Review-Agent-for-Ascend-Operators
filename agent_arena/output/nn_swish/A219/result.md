# Ascend NPU 算子代码审查报告

**文件**: `test_swish_stress.cpp`  
**审查重点**: 资源管理、内存泄漏

---

### Bug #1: 循环内Device内存分配未释放（严重内存泄漏）

- **位置**: 第7-11行，`for` 循环体内
- **类型**: 内存泄漏（Device Memory Leak）
- **严重程度**: 严重（Critical）
- **描述**: 循环执行1000次，每次通过 `aclrtMalloc` 分配16MB的Device内存，但循环体内没有调用 `aclrtFree(ws)` 释放内存，循环结束后也未释放。由于 `ws` 是循环体内的局部变量，每次迭代结束后指针丢失，导致之前分配的内存永远无法回收。总计泄漏 1000 * 16MB = 16GB Device内存。
- **触发条件**: 程序正常执行即触发。循环运行数次后，NPU Device内存耗尽，后续 `aclrtMalloc` 将返回错误码（内存不足），但代码也未检查返回值。
- **测试方案**: 运行程序并监控NPU Device内存使用量（通过 `npu-smi info`），观察内存持续增长直至OOM；或在循环中添加日志打印 `aclrtMalloc` 返回值，验证后期分配失败。

**修复建议**:
```cpp
for (int i = 0; i < 1000; i++) {
    void* ws = nullptr;
    aclrtMalloc(&ws, 16*1024*1024, ACL_MEM_MALLOC_HUGE_FIRST);
    // ... 使用 ws ...
    aclrtFree(ws);  // 添加释放
}
```

### Bug #2: ACL API返回值未检查

- **位置**: 第3、4、6、9行（`aclInit`、`aclrtSetDevice`、`aclrtCreateStream`、`aclrtMalloc`）
- **类型**: 错误处理缺失（Missing Error Handling）
- **严重程度**: 中等（Medium）
- **描述**: 所有ACL API调用均未检查返回的 `aclError` 状态码。若 `aclrtSetDevice` 或 `aclrtCreateStream` 失败，后续操作将基于无效资源执行，可能导致未定义行为。特别是循环内 `aclrtMalloc` 失败后继续执行，`ws` 保持 `nullptr`，若后续有解引用则会崩溃。
- **触发条件**: 设备不可用、资源不足或驱动异常时触发。
- **测试方案**: 在无NPU设备或设备ID错误的环境中运行，验证程序是否出现段错误或无意义的后续调用。

---

### Bug #3: 压力测试场景下局部变量指针作用域不当

- **位置**: 第8行，`void* ws` 声明在循环体内
- **类型**: 资源管理设计缺陷（Resource Management Design Flaw）
- **严重程度**: 中等（Medium）
- **描述**: `ws` 声明为循环局部变量，每次迭代结束后指针超出作用域。即使想在循环外统一释放也无法做到，因为只能访问到最后一次分配的地址（实际连最后一次也无法访问）。如果是压力测试目的（分配-使用-释放循环），指针应在释放后再进入下一次迭代；如果是批量分配目的，应使用数组/容器保存所有指针。
- **触发条件**: 代码逻辑本身即存在此问题。
- **测试方案**: 使用AddressSanitizer或Valgrind（Host侧模拟）检测泄漏点，确认每次循环迭代的分配都未被释放。
