# Swish 算子定义代码审查报告

**文件**: `swish_def.cpp`  
**审查范围**: 算子定义、文件路径、平台配置

---

### Bug 1: 无效的 SoC 平台标识符 "mc62cm12a"

| 项目 | 内容 |
|------|------|
| **位置** | 第 42 行: `this->AICore().AddConfig("mc62cm12a", aicoreConfig);` |
| **类型** | 算子定义错误 - 无效平台配置 |
| **严重程度** | 高 |
| **描述** | `"mc62cm12a"` 不是合法的 Ascend NPU SoC 平台标识符。CANN 框架支持的合法标识符包括 `ascend310`、`ascend310p`、`ascend910`、`ascend910b`、`ascend910_93`、`ascend910_95` 等。使用无效标识符会导致算子在目标平台上无法被正确调度和执行，AddConfig 调用将无效或产生运行时错误。 |
| **触发条件** | 在任何非 ascend910_95 的平台上部署并调用该算子时，预期的第二平台配置无法生效，算子调度失败。 |
| **测试方案** | 1. 在 CANN 环境中编译该算子定义，检查是否有平台不识别的告警或错误；2. 尝试在 Ascend 310P/910B 等平台上加载算子，验证是否能正确识别并执行；3. 将 `"mc62cm12a"` 替换为合法的 SoC 标识符（如 `"ascend310p"`）后对比验证。 |

### Bug 2: opFile.value 引用的内核文件名可能不匹配

| 项目 | 内容 |
|------|------|
| **位置** | 第 40 行: `.ExtendCfgInfo("opFile.value", "swish_opt")` |
| **类型** | 文件路径错误 - 内核文件引用不一致 |
| **严重程度** | 中 |
| **描述** | `opFile.value` 指定为 `"swish_opt"`，这意味着框架在运行时将查找名为 `swish_opt` 的内核实现文件（如 `swish_opt.cpp` / `swish_opt.py`）。对于标准 Swish 算子，内核文件通常命名为 `swish`。如果实际内核实现文件名不是 `swish_opt`，将导致算子编译或运行时找不到对应内核实现，出现 "kernel not found" 错误。 |
| **触发条件** | 算子编译阶段或首次运行时，框架根据 `opFile.value` 查找内核实现文件，若工程中不存在 `swish_opt.cpp`/`swish_opt.py` 则直接报错。 |
| **测试方案** | 1. 检查算子工程目录下是否存在 `swish_opt.cpp` 或 `swish_opt.py` 内核实现文件；2. 若不存在，将该值修改为实际内核文件名（如 `"swish"`）；3. 执行算子编译流程，验证是否能成功找到并编译内核。 |

### Bug 3: PrecisionReduceFlag 对 BF16 数据类型可能导致精度严重损失

| 项目 | 内容 |
|------|------|
| **位置** | 第 39 行: `.PrecisionReduceFlag(true)` |
| **类型** | 算子定义缺陷 - 精度配置不当 |
| **严重程度** | 中 |
| **描述** | `PrecisionReduceFlag(true)` 允许框架对计算进行精度降低优化。Swish 函数 `f(x) = x * sigmoid(x)` 内部包含 sigmoid 计算，sigmoid 在输入绝对值较大时对精度敏感。当输入数据类型为 `ge::DT_BF16`（仅 8 位尾数）时，启用精度降低可能导致 sigmoid 中间结果精度严重不足，最终输出与标杆值偏差超出容忍范围。 |
| **触发条件** | 使用 BF16 数据类型输入，且输入值绝对值较大（如 |x| > 4）时，精度降低后 sigmoid 计算误差累积，输出精度不达标。 |
| **测试方案** | 1. 构造 BF16 类型、值域覆盖 [-10, 10] 的测试输入；2. 分别在 `PrecisionReduceFlag(true)` 和 `PrecisionReduceFlag(false)` 配置下运行算子；3. 对比输出与 FP32 标杆的相对误差，验证 BF16 场景下精度是否达标（通常要求相对误差 < 0.01）。 |
