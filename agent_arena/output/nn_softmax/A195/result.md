# A195 代码审查报告 - softmax_v2_base.h

## Bug 1: FP32 转 FP16 舍入模式配置为 CAST_NONE 导致精度损失

- **位置**: 第 40 行
- **类型**: 精度问题
- **严重程度**: 中
- **描述**: `castTraitFp32ToFp16` 中 `RoundMode` 设置为 `CAST_NONE`（无舍入/截断模式）。在 FP32 转 FP16 的类型转换中，不使用舍入会导致系统性的精度偏差。正确的做法应使用 `CAST_RINT`（四舍五入到最近偶数），这是 IEEE 754 推荐的默认舍入方式。对比同算子的 A196 版本，其使用了 `CAST_RINT`。
- **触发条件**: 当输入为 FP16 类型且 `halfToFloat_` 为 false 时，计算过程中 FP32 中间结果转回 FP16 输出时触发。尤其在 softmax 输出值接近 0 或接近 1 的边界区域，截断误差会更明显。
- **测试方案**: 
  1. 使用 FP16 输入/输出运行 softmax，与标准实现（使用 CAST_RINT）对比结果精度
  2. 构造输入使 softmax 输出在 FP16 精度边界附近（如极大/极小值），验证尾数精度
  3. 统计大量随机输入下的平均绝对误差，与 CAST_RINT 版本对比
