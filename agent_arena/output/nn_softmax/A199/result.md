# Code Review: test_softmax_pipeline.cpp (A199)

## Bug 1: 缺少 Stream 同步导致读取未完成的计算结果

- **位置**: 第 18 行（aclrtMemcpy 调用之前）
- **类型**: 竞态条件 / 同步缺失
- **严重程度**: 高
- **描述**: 在第 15 行注释处会启动异步 kernel，但在第 18 行直接调用 `aclrtMemcpy` 从 device 拷贝输出数据到 host，中间缺少 `aclrtSynchronizeStream(stream)` 调用。异步 kernel 可能尚未执行完毕，导致读取到未初始化或部分计算的数据，产生不确定性结果。
- **触发条件**: 当实际在第 15 行位置添加 kernel launch 后，kernel 执行时间超过 host 侧到达 memcpy 的时间（几乎总是如此）。
- **测试方案**: 在 kernel launch 和 memcpy 之间不加同步，对比加同步后的输出结果。不加同步时输出应不一致或为随机值。修复方法：在第 17 行前插入 `aclrtSynchronizeStream(stream);`。

## Bug 2: aclrtMalloc 返回值未检查

- **位置**: 第 12-13 行
- **类型**: 错误处理缺失
- **严重程度**: 中
- **描述**: `aclrtMalloc` 可能因显存不足等原因失败并返回非零错误码，但代码未检查返回值。若分配失败，`devInput`/`devOutput` 保持 nullptr，后续 memcpy 和 kernel launch 会访问空指针导致程序崩溃或未定义行为。
- **触发条件**: 设备显存不足，或设备未正确初始化时调用 malloc。
- **测试方案**: 在显存接近耗尽的情况下运行测试，验证程序是否因空指针而崩溃。修复：检查返回值并在失败时打印错误信息并退出。

## Bug 3: aclInit/aclrtSetDevice/aclrtCreateStream 返回值未检查

- **位置**: 第 5-8 行
- **类型**: 错误处理缺失
- **严重程度**: 低
- **描述**: ACL 初始化相关函数均可能失败（如设备不存在、驱动未加载等），但返回值被忽略。在实际部署环境中，若初始化失败而继续执行将导致后续所有操作行为未定义。
- **触发条件**: 目标设备不可用、驱动版本不兼容、或 acl.json 配置错误。
- **测试方案**: 在无 NPU 设备的环境中运行，观察是否有合理的错误提示。修复：检查所有 ACL API 返回值。
