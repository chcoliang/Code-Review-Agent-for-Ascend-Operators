# Code Review: test_softmax_stress.cpp

## Bug 1: 循环内分配内存未释放（内存泄漏）
- **位置**: 行 12-13
- **类型**: 内存泄漏
- **严重程度**: 高
- **描述**: 在 for 循环中每次迭代通过 `aclrtMalloc` 分配 16MB 设备内存，但循环体内没有对应的 `aclrtFree(workspace)` 调用。循环执行 1000 次，总计泄漏 16GB 设备内存，极有可能耗尽 NPU 显存导致程序崩溃或后续分配失败。
- **触发条件**: 直接运行程序即可触发；循环迭代数次后设备内存耗尽，`aclrtMalloc` 将返回错误码。
- **测试方案**: 运行程序并监控 NPU 设备内存使用量，观察内存是否持续增长直到 OOM；或检查 `aclrtMalloc` 返回值是否在若干次迭代后变为非零错误码。

## Bug 2: 未检查 aclInit 返回值
- **位置**: 行 5
- **类型**: 错误处理缺失
- **严重程度**: 中
- **描述**: `aclInit(nullptr)` 的返回值未检查。若初始化失败（如驱动未加载、环境异常），后续所有 ACL 调用行为未定义，可能导致段错误或静默错误。
- **触发条件**: 在未安装 NPU 驱动或驱动异常的环境中运行程序。
- **测试方案**: 在无 NPU 驱动环境下运行，验证程序是否能优雅退出而非崩溃。

## Bug 3: 未检查 aclrtSetDevice 返回值
- **位置**: 行 6
- **类型**: 错误处理缺失
- **严重程度**: 中
- **描述**: `aclrtSetDevice(0)` 返回值未检查。设备不存在或繁忙时调用失败，后续流创建和内存分配将在无效上下文中执行。
- **触发条件**: 在无 device 0 的机器上运行，或 device 0 已被独占使用。
- **测试方案**: 指定一个不存在的设备 ID（如修改为 99），观察后续调用是否产生不可预期行为。

## Bug 4: 未检查 aclrtCreateStream 返回值
- **位置**: 行 8
- **类型**: 错误处理缺失
- **严重程度**: 中
- **描述**: `aclrtCreateStream(&stream)` 返回值未检查。若流创建失败，`stream` 为未初始化值，后续 `aclrtDestroyStream(stream)` 将操作无效句柄。
- **触发条件**: 设备上下文无效或资源耗尽时流创建失败。
- **测试方案**: 在 aclrtSetDevice 失败的前提条件下调用 CreateStream，验证是否产生异常。

## Bug 5: 未检查 aclrtMalloc 返回值
- **位置**: 行 12
- **类型**: 错误处理缺失
- **严重程度**: 高
- **描述**: 循环内 `aclrtMalloc` 返回值未检查。由于 Bug 1 的内存泄漏，分配必然在某次迭代失败，但程序无感知地继续执行，若后续使用 workspace 指针将导致空指针访问。
- **触发条件**: 循环迭代至设备内存耗尽时，aclrtMalloc 返回失败但 workspace 仍为 nullptr。
- **测试方案**: 减小设备可用内存或增大分配大小，验证程序在分配失败时的行为。

## Bug 6: workspace 指针在循环每次迭代被覆盖
- **位置**: 行 11-12
- **类型**: 资源管理错误
- **严重程度**: 高
- **描述**: `workspace` 在每次循环迭代中被重新声明并分配新地址，前一次分配的地址丢失，无法再释放。即使想在循环后释放，也只能拿到最后一次的指针（且由于是局部变量，循环外不可见）。这是内存泄漏的根本原因。
- **触发条件**: 循环执行第 2 次迭代时，第 1 次分配的内存地址即丢失。
- **测试方案**: 使用内存分析工具（如 ACL 的内存统计接口）在循环前后对比设备已分配内存量，确认存在 999 份未释放的 16MB 内存块。
