# 代码审查报告: test_conv_stress.cpp

## Bug 1: 循环内存分配未释放导致严重内存泄漏

- **位置**: 第 9 行 (`aclrtMalloc(&ws, 64*1024*1024, ACL_MEM_MALLOC_HUGE_FIRST);`)
- **类型**: 内存泄漏
- **严重程度**: 高
- **描述**: 在 for 循环（500次迭代）中，每次迭代分配 64MB 设备内存，但从未调用 `aclrtFree(ws)` 释放。循环结束后 `ws` 指针为局部变量，离开作用域后无法再释放。总计泄漏 500 * 64MB = 32GB 设备内存，远超 Ascend 910B 的 HBM 容量，会导致 OOM。
- **触发条件**: 程序正常执行即触发，循环迭代数次后设备内存耗尽，后续 `aclrtMalloc` 调用将失败。
- **测试方案**: 运行程序并监控 NPU 设备内存使用（如通过 `npu-smi info`），观察内存持续增长且不回收；或检查 `aclrtMalloc` 返回值，在若干次迭代后应返回内存不足错误码。

## Bug 2: aclrtMalloc 返回值未检查

- **位置**: 第 9 行
- **类型**: 错误处理缺失
- **严重程度**: 中
- **描述**: `aclrtMalloc` 可能因设备内存不足而失败（尤其在泄漏场景下），但返回值未检查。失败后 `ws` 仍为 `nullptr`，若后续有使用该指针的操作将导致未定义行为。
- **触发条件**: 设备内存耗尽时 `aclrtMalloc` 返回非 ACL_SUCCESS 错误码，程序继续执行而不感知错误。
- **测试方案**: 在内存紧张条件下运行，验证程序是否能正确检测到分配失败并做相应处理。

## Bug 3: aclInit 返回值未检查

- **位置**: 第 3 行 (`aclInit(nullptr);`)
- **类型**: 错误处理缺失
- **严重程度**: 中
- **描述**: `aclInit` 初始化失败时（如驱动未加载、配置错误），后续所有 ACL 调用行为未定义，但此处未检查返回值。
- **触发条件**: ACL 运行时环境异常时触发。
- **测试方案**: 在未安装驱动的环境中运行，验证程序行为。

## Bug 4: aclrtSetDevice 返回值未检查

- **位置**: 第 4 行 (`aclrtSetDevice(0);`)
- **类型**: 错误处理缺失
- **严重程度**: 中
- **描述**: 设备设置失败（如设备不存在或被占用）时未检查返回值，后续流创建和内存分配将在无效上下文中执行。
- **触发条件**: 设备 0 不可用或已被其他进程独占。
- **测试方案**: 在无 NPU 设备或设备繁忙的环境中运行，检查是否有合理的错误退出。

## Bug 5: aclrtCreateStream 返回值未检查

- **位置**: 第 6 行 (`aclrtCreateStream(&stream);`)
- **类型**: 错误处理缺失
- **严重程度**: 中
- **描述**: 流创建失败时 `stream` 值未定义，后续 `aclrtDestroyStream(stream)` 将销毁无效流，可能导致崩溃。
- **触发条件**: 设备上下文无效或资源耗尽时。
- **测试方案**: 模拟设备初始化失败场景，检查是否对 stream 操作产生异常。

## Bug 6: 循环内 ws 指针每次被覆盖，前次分配地址丢失

- **位置**: 第 8-9 行
- **类型**: 资源管理 / 逻辑错误
- **严重程度**: 高
- **描述**: `ws` 在循环体内声明并在每次迭代中被新分配覆盖。即使想在循环外释放，也只能访问到最后一次分配的地址（实际上由于作用域限制，循环外也无法访问 `ws`）。这是设计层面的资源管理缺陷。
- **触发条件**: 程序正常执行即触发。
- **测试方案**: 使用内存检测工具（如 ACL 内置的内存泄漏检测）运行，统计分配/释放次数是否匹配。
