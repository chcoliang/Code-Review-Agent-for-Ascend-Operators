# 代码审查报告: test_gelu_stress.cpp

## Bug 1: 循环内存分配未释放导致严重内存泄漏

- **位置**: 第 9 行 (`aclrtMalloc(&ws, 16*1024*1024, ACL_MEM_MALLOC_HUGE_FIRST)`)
- **类型**: 内存泄漏
- **严重程度**: 高
- **描述**: 在 `for` 循环中每次迭代分配 16MB 设备内存，但循环体内没有对应的 `aclrtFree(ws)` 调用。循环执行 1000 次，总计泄漏 16GB 设备内存，极易导致 NPU 设备内存耗尽 (OOM)。
- **触发条件**: 程序正常执行即触发，循环每次迭代都会泄漏 16MB。
- **修复建议**: 在循环末尾添加 `aclrtFree(ws);`。
- **测试方案**: 运行程序并监控 NPU 设备内存使用量（如通过 `npu-smi info`），观察内存是否持续增长直至 OOM；或在循环次数较少时检查循环结束后设备可用内存是否减少。

## Bug 2: 局部变量 ws 作用域导致内存句柄丢失

- **位置**: 第 8 行 (`void* ws = nullptr;`)
- **类型**: 资源管理缺陷
- **严重程度**: 高
- **描述**: `ws` 在循环体内声明为局部变量，每次循环结束后指针超出作用域，导致之前分配的设备内存地址丢失，即使后续想释放也无法获取到有效地址。这使得内存泄漏不可恢复。
- **触发条件**: 程序正常执行，循环每次迭代结束时指针丢失。
- **修复建议**: 若需要保留所有分配，应使用数组/容器存储指针；若为压力测试，应在每次迭代末尾释放。
- **测试方案**: 使用内存泄漏检测工具或在循环后尝试释放内存，验证是否存在不可达的已分配内存。

## Bug 3: aclrtMalloc 返回值未检查

- **位置**: 第 9 行
- **类型**: 错误处理缺失
- **严重程度**: 中
- **描述**: `aclrtMalloc` 可能因设备内存不足等原因返回错误码（非 `ACL_SUCCESS`），但代码未检查返回值。当内存分配失败时，`ws` 仍为 `nullptr`，后续如有使用将导致未定义行为。在压力测试场景中，由于持续泄漏，后续分配极有可能失败。
- **触发条件**: 设备内存不足时 `aclrtMalloc` 返回失败。
- **修复建议**: 检查返回值，失败时打印错误信息并 break 或做异常处理。
- **测试方案**: 在设备内存已接近满载时运行，验证程序是否能正确处理分配失败。

## Bug 4: aclInit 返回值未检查

- **位置**: 第 3 行
- **类型**: 错误处理缺失
- **严重程度**: 中
- **描述**: `aclInit` 初始化失败时后续所有 ACL 调用行为未定义，但代码未检查其返回值。
- **触发条件**: ACL 运行时环境异常或重复初始化时。
- **修复建议**: 检查返回值，失败时直接返回错误。
- **测试方案**: 在未正确安装驱动的环境中运行，验证是否有合理的错误提示。

## Bug 5: aclrtSetDevice 返回值未检查

- **位置**: 第 4 行
- **类型**: 错误处理缺失
- **严重程度**: 中
- **描述**: 设备设置失败（如设备不存在）时未做任何处理，后续流创建和内存分配将在无效上下文中执行。
- **触发条件**: 指定的设备 ID 不存在或设备故障时。
- **修复建议**: 检查返回值，失败时清理已初始化的资源并退出。
- **测试方案**: 在无 NPU 设备或设备 ID 不存在的环境中运行。

## Bug 6: aclrtCreateStream 返回值未检查

- **位置**: 第 6 行
- **类型**: 错误处理缺失
- **严重程度**: 低
- **描述**: 流创建失败时 `stream` 变量未被正确初始化，后续 `aclrtDestroyStream(stream)` 可能传入无效句柄。
- **触发条件**: 系统资源不足导致流创建失败。
- **修复建议**: 检查返回值，失败时跳过后续操作。
- **测试方案**: 模拟资源受限场景，验证流创建失败后程序行为。
