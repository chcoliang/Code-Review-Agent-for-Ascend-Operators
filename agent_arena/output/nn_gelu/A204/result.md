# GELU DAG 算子代码审查报告

**文件**: `gelu_dag.h`  
**平台**: Ascend 910B  

---

## Bug 1: Mask 未按迭代更新，最后一次迭代可能越界访问

- **位置**: 第 50 行
- **类型**: 计算逻辑 / 内存越界
- **严重程度**: 高
- **描述**: `UpdateMask` 始终使用总元素数 `count` 来计算 mask，而没有根据当前迭代剩余的元素数进行调整。在最后一次迭代中，如果 `count` 不是 `vl`（向量长度）的整数倍，mask 仍然覆盖了超出有效数据范围的元素，导致：(1) 读取 src 中越界的脏数据参与计算；(2) 写入 dst 时覆盖越界内存区域。
- **正确做法**: 应使用 `UpdateMask<T, MicroAPI::RegTraitNumOne>(min(count - loopIdx * vl, vl))` 或在每次迭代后递减 count。
- **触发条件**: 当输入 tensor 的元素总数不是向量寄存器宽度（如 256B/sizeof(float)=64 个 float）的整数倍时触发。
- **测试方案**: 使用非对齐长度（如 65、100、127 个元素）的输入 tensor 执行 GELU 计算，对比标准 GELU 输出，检查最后几个元素是否正确以及是否有内存踩踏。

## Bug 2: 输出 Cast 使用 CAST_MODE_RINT 导致结果被取整

- **位置**: 第 77 行
- **类型**: 精度错误
- **严重程度**: 高
- **描述**: `OpResultCast` 将 float 类型的 GELU 计算结果转换回输入类型 U（通常为 half/float16）时，使用了 `CAST_MODE_RINT`（值为 1，表示 round-to-nearest-integer）。这会将 GELU 的连续浮点输出四舍五入为整数值后再转换类型。例如 GELU(0.5)≈0.3457 会被取整为 0.0，GELU(1.0)≈0.8413 会被取整为 1.0。这完全破坏了算子的数值精度。
- **正确做法**: 应使用 `CAST_MODE_NONE`（值为 0），即 `Vec::Cast<U, T, CAST_MODE_NONE>`，直接进行类型转换而不取整。
- **触发条件**: 当模板参数 U != float（即 U 为 half 等类型需要 cast 时）始终触发。
- **测试方案**: 使用 float16 输入，值为 [0.1, 0.5, 1.0, 2.0]，验证输出是否为连续浮点值而非取整后的整数值。与 PyTorch `torch.nn.functional.gelu()` 的结果对比。

## Bug 3: MemCfg 使用 LEVEL_1 (L1) 而非 UB，内存层级错误

- **位置**: 第 81 行
- **类型**: 内存层级错误
- **严重程度**: 高
- **描述**: `MemCfg` 配置为 `MemLevel::LEVEL_1`，即 L1 Buffer。在 Ascend 910B 架构中，Vector 计算单元只能直接操作 UB（Unified Buffer）中的数据，不能直接对 L1 Buffer 中的数据进行向量运算。DAG 调度框架中的中间 tensor 应分配在 UB 上。使用 L1 会导致：(1) 向量指令无法正确访问数据；(2) 可能在运行时报内存访问错误或产生未定义行为。
- **正确做法**: 应使用 `MemLevel::LEVEL_UB` 或对应 UB 层级的枚举值。
- **触发条件**: 始终触发，任何调用该算子的场景都会受影响。
- **测试方案**: 运行任意输入的 GELU 算子，检查是否出现 runtime error 或 HCCP 报错；对比改为 UB 后的运行结果。

## Bug 4: TANH_APPROX_FACTOR 精度损失（float 存储 double 计算结果）

- **位置**: 第 25 行
- **类型**: 精度
- **严重程度**: 低
- **描述**: `1 / 0.044715` 的精确值为 22.36268...，以 double 精度计算后存储为 `const float`，会有约 1e-7 量级的精度损失。虽然对 GELU 最终结果影响很小，但若追求高精度可以直接写明 float 字面量 `22.3627f` 或保持 double。
- **触发条件**: 始终存在，但影响极小。
- **测试方案**: 大规模随机输入（1M 元素），对比使用 double 精度常量时的最大绝对误差。

---

## Bug 5: 缺少非 float 类型的计算路径

- **位置**: 第 47 行 (`if constexpr(std::is_same_v<T, float>)`)
- **类型**: 计算逻辑缺陷
- **严重程度**: 中
- **描述**: `GeluCustom` 构造函数中仅在 `T == float` 时执行计算逻辑。如果 DAG 框架以 `T = half` 实例化此模板（虽然当前 GeluDAG 模板默认 T=float），dst tensor 将不会被写入任何数据，输出为未初始化的垃圾值。代码缺少 `else` 分支或 `static_assert` 来防止误用。
- **触发条件**: 当用户显式指定 `T` 为非 float 类型时触发。
- **测试方案**: 尝试以 `GeluDAG<half, half>` 实例化并执行，检查输出是否为全零或垃圾值。
