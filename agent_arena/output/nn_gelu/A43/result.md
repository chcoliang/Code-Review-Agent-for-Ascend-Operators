# Gelu 算子定义代码审查报告

**文件**: `gelu_def.cpp`

---

### Bug 1: opFile.value 配置的文件名错误

- **位置**: 第 41 行
- **类型**: 文件路径配置错误
- **严重程度**: 严重 (High)
- **描述**: `ExtendCfgInfo("opFile.value", "gelu_opt")` 将算子实现文件指定为 `gelu_opt`，但 Gelu 算子的标准 kernel 实现文件应命名为 `gelu`。框架在编译时会根据此配置查找对应的算子实现文件（如 `gelu_opt.cpp` 或 `gelu_opt.py`），若实际文件名为 `gelu`，则会导致找不到算子实现文件，编译失败。
- **触发条件**: 算子编译阶段，框架根据 `opFile.value` 定位 kernel 实现文件时，若实际实现文件名为 `gelu` 而非 `gelu_opt`，将触发文件找不到错误。
- **测试方案**: 构建算子包，观察编译日志是否报告找不到 `gelu_opt` 对应的实现文件；将值改为 `"gelu"` 后验证编译通过。

---

### Bug 2: 无效的 SoC 平台标识符 "mc62cm12a"

- **位置**: 第 43 行
- **类型**: 算子定义/平台配置错误
- **严重程度**: 严重 (High)
- **描述**: `this->AICore().AddConfig("mc62cm12a", aicoreConfig)` 中的 `"mc62cm12a"` 不是有效的 Ascend SoC 平台标识符。合法的标识符包括 `"ascend910"`, `"ascend910b"`, `"ascend310p"`, `"ascend910_95"` 等。使用无效平台名会导致该配置不被任何硬件匹配，算子在目标平台上无法调度执行。
- **触发条件**: 算子注册阶段或算子部署到目标硬件时，框架无法识别 `"mc62cm12a"` 平台，该 AddConfig 配置无效，若目标平台依赖此配置则算子不可用。
- **测试方案**: 1) 查阅当前 CANN 版本支持的 SoC 列表，确认正确的平台标识符（如应为 `"ascend910b"` 或其他）；2) 修改为正确标识符后，在目标硬件上执行算子验证调度成功。
