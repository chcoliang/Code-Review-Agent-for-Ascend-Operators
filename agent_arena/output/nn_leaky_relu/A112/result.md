# aclnn_leaky_relu.cpp 代码审查报告

## Bug 列表

### Bug 1: negativeSlope 被错误地乘以 0.5

- **位置**: 第 104 行
- **类型**: 算法逻辑错误
- **严重程度**: 高 (Critical)
- **描述**: 在调用 `l0op::LeakyRelu` 时，`negativeSlope` 参数被错误地乘以了 0.5：
  ```cpp
  auto output = l0op::LeakyRelu(selfContiguous, negativeSlope->ToFloat() * 0.5, uniqueExecutor.get());
  ```
  LeakyReLU 的标准数学定义为：`f(x) = x if x >= 0, f(x) = negativeSlope * x if x < 0`。用户传入的 `negativeSlope` 应当直接使用，不应乘以 0.5。这会导致所有负值区域的输出结果偏小一半，计算结果错误。
- **触发条件**: 任何输入包含负值且 negativeSlope 非零的情况下均会触发，即几乎所有正常使用场景。
- **修复建议**: 将 `negativeSlope->ToFloat() * 0.5` 改为 `negativeSlope->ToFloat()`。
- **测试方案**:
  1. 构造输入 tensor `[-1.0, -2.0, 1.0, 2.0]`，设置 `negativeSlope = 0.01`。
  2. 预期输出为 `[-0.01, -0.02, 1.0, 2.0]`。
  3. 当前错误实现会输出 `[-0.005, -0.01, 1.0, 2.0]`（负值部分偏小一半）。

### Bug 2: 未对输出 tensor 的数据类型进行校验

- **位置**: 第 67-78 行 (`CheckParams` 函数)
- **类型**: 参数校验不完整
- **严重程度**: 中 (Medium)
- **描述**: `CheckDtypeValid` 仅校验了输入 `self` 的数据类型是否在支持列表中，但未对输出 `out` 的数据类型进行校验。如果用户传入一个不支持的输出数据类型（如 INT32），虽然后续 `l0op::Cast` 可能会处理，但可能导致未定义行为或静默产生错误结果。
- **触发条件**: 用户为 `out` 指定了一个不在支持列表中的数据类型时触发。
- **测试方案**:
  1. 构造 float 类型输入 tensor，输出 tensor 设为 INT8/INT32 类型。
  2. 验证是否能正确报错或产生正确结果。

### Bug 3: extern "C" 块中包含 C++ 代码存在潜在链接问题

- **位置**: 第 27-29 行，第 137-139 行
- **类型**: 代码规范/潜在兼容性问题
- **严重程度**: 低 (Low)
- **描述**: `extern "C"` 块内定义了使用 `std::initializer_list`、lambda 等 C++ 特性的静态变量和函数。虽然在纯 C++ 编译环境下通常不会出问题（因为有 `#ifdef __cplusplus` 保护），但将导出函数（`aclnnLeakyReluGetWorkspaceSize` 等）置于 `extern "C"` 中会使用 C 链接约定，这对于需要 C 接口调用的场景是正确做法。但内部静态辅助函数和变量不需要放在此块内，如果未来有其他编译环境可能引发问题。
- **触发条件**: 一般情况下不会触发，仅在特殊编译环境或工具链下可能出现。
- **测试方案**: 代码规范审查，确认编译无警告。
